# 2026-10-18 — Anvil 2/3 tmux 세션·상태·알림 (일괄 승급 회고)

## 계획 대비 실제
- 계획대로 된 것: Anvil 전용 tmux 소켓 세션(앱 종료 뒤에도 살아 있음), 훅 상태 파일(waiting·working·ended), `--settings` 훅 병합(대체 아님 — Stop 이벤트 `hookCount: 2`), 앱 재시작 시 자동 재부착, 사용자 기본 tmux 소켓 오염 없음.
- 어긋난 것:
  - **GUI 앱 최소 환경.** Finder에서 띄운 앱엔 PATH(claude·tmux 못 찾음)뿐 아니라 LANG도 없어 tmux가 한글을 `_`로 바꿨다 → 로그인 셸 PATH + `-u` + `LANG`(없으면 en_US.UTF-8)을 tmux 서버·클라이언트·claude에 넘김.
  - **한글 IME 수리에 4라운드(r2~r5), 재계획 상한을 3→4→6으로 두 번 올림.** r2(keydown 막기)·r3(compositionend만 보내기)는 원인을 추측한 수정이라 둘 다 헛걸음. r3에 넣은 이벤트 로그로 r4에서야 원인이 보였다: WKWebView는 한글에 composition 이벤트를 **0건** 보내고 `insertText`(새 음절 첫 자모) → `insertReplacementText`(조합 바꿔치기)로만 보내며, IME 키 keydown(229)은 input **뒤에** 온다. r5에서 키 순서에 기대지 않게 고쳐 통과.
  - **알림 플러그인이 macOS 27에서 조용히 무시됨.** tauri-plugin-notification → mac-notification-sys가 폐기된 NSUserNotificationCenter를 써서 허용 요청만 뜨고 알림이 안 옴 → 앱도 훅과 같은 `osascript display notification`으로 통일(r6).
  - 훅 이벤트에 계획에 없던 `PostToolUse → working`을 더함(권한 승인 뒤 '작업 중'으로 돌아올 길이 없었음).

## 배운 점
- 다음엔 다르게:
  - **환경 의존 입력 버그(IME·WebView 이벤트)는 고치기 전에 이벤트 순서부터 기록한다.** 추측 수정 두 번이 상한을 태웠다 — 첫 실패에서 바로 keydown·input·composition·xterm onData 순서 로그를 넣었으면 r2·r3를 건너뛸 수 있었다.
  - **WKWebView(Tauri macOS)에서 한글은 composition 이벤트가 아니라 input 이벤트(`insertText`·`insertReplacementText`)로 해석한다.** keydown(229)이 input 뒤에 오므로 키 순서 조건을 쓰지 않는다. xterm이 따로 보내는 한글은 붙여넣기 중이 아닐 때만 버린다(`Terminal.svelte`).
  - **GUI 앱에서 외부 명령을 띄울 땐 PATH·LANG을 명시한다** — 회귀 테스트로 고정함.
  - **macOS 알림은 `osascript display notification`을 쓴다.** tauri 알림 플러그인은 macOS 27에서 무시된다.

## 후속 작업 후보
- 한글 IME 해석 로직(`Terminal.svelte`의 input 이벤트 처리)을 순수 함수로 빼고 프런트 단위 테스트로 고정하기 — 지금은 프런트 테스트 도구가 없어 사람 UAT로만 확인된다
