# 2026-11-01 — Windows·Linux에서 앱이 돌고, 세 OS e2e가 CI에서 돈다 (데스크톱 앱 4/6)

## 계획 대비 실제
- 계획대로 된 것: Linux는 node-pty가 CI에서 컴파일돼 Electron에서 그대로 돌았다(S2). README Windows 절(S4). 세 OS Electron 스모크가 CI `41180714200`에서 통과했다.
- 어긋난 것: Windows node-pty가 실행 파일을 서버 Path에서 이름 그대로만 찾아 `claude.exe`를 못 찾았다 → `findCommand`·`spawnTarget`(S1). e2e 잡은 안정될 때까지 9번 고쳤고 원인은 모두 테스트·환경 쪽이었다(러너에 claude 없음 → `ANVIL_SKIP_DEPS`, 화면 언어, ConPTY가 테스트 프로세스를 붙잡음, `close()` 멈춤, 가끔 `app.quit` 뒤 앱이 남음)(S3). 깨끗한 Windows VM에서 CI가 못 잡은 결함 셋이 나왔다(뜬 뒤 깐 Git이 PATH에 없음, `node.cmd`를 `execFile`로 못 부름, Electron에 `prompt()` 없음 → 폴더 창은 preload+`dialog`로, 사람 결정)(S5).

## 배운 것
- 다음에 다르게 할 것: Windows 서버 프로세스의 PATH는 뜰 때 값으로 굳는다. 실행 중에 설치한 도구는 표준 설치 폴더를 직접 붙여야 보인다. Windows에서 `.cmd`는 `execFile`·node-pty로 바로 부를 수 없다. 이름으로 찾지 말고 경로를 쓰고, `.cmd`·`.bat`은 `cmd.exe`로 감싼다. CI만으로는 첫 실행 경로(준비물 자동 설치)가 검증되지 않으니 깨끗한 VM 확인을 계획에 넣는다(이번에 결함 셋을 거기서 찾았다). Electron 렌더러에는 `prompt()`가 없다.
