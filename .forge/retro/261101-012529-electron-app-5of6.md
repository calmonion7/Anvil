# 2026-11-01 — 설치 파일 릴리스와 세 OS 공통 자체 업데이터 (데스크톱 앱 5/6)

## 계획 대비 실제
- 계획대로 된 것: `release.yml`이 electron-builder 3잡으로 설치 파일 6개와 `SHA256SUMS.txt`를 올려 v0.2.0이 공개됐다(S1). 업데이터 공통부(확인 → 체크섬 → 세션 가드 → 교체 → 복구)는 테스트 먼저 썼다(S2).
- 어긋난 것: OS별 교체 스크립트(S3)는 구현을 먼저 썼고 CI·UAT에서 결함 넷이 나왔다. ① mac 테스트가 번들 ID로 종료를 청해 설치된 실제 앱을 끌 수 있었다. ② Linux `pgrep -f`가 스크립트 자신을 잡아 스스로 `pkill -9`했다. ③ Windows 배치에서 `call` 없이 설치 프로그램을 불러 돌아오지 않았다. ④ 서버의 `ELECTRON_RUN_AS_NODE=1`을 물려받아 다시 연 앱이 창 없이 꺼졌다. 이 Mac 전환(S4)에서는 launchd 에이전트·빌드 클론을 찾지 못했고, `.dmg` 설치는 사람 결정으로 6/6 뒤로 미뤘다. 옛 `e2e-desktop` 하네스 삭제를 6/6에서 당겨 왔다.

## 배운 것
- 다음에 다르게 할 것: 앱을 끄는 테스트·스크립트는 번들 ID가 아니라 바꿀 그 경로에만 청한다. 같은 ID의 설치본이 같이 꺼진다. 자식 프로세스에 넘길 환경은 허용 목록으로 만든다. `ELECTRON_RUN_AS_NODE` 같은 서버 전용 값이 앱 재실행으로 새면 조용히 실패한다. `pgrep -f` 패턴을 인자로 넘기면 스크립트 자신이 걸린다 → 환경변수로 넘긴다. 업데이터가 든 첫 버전은 실제 릴리스로 업데이트를 시험할 수 없으니 가짜 릴리스 서버(`ANVIL_UPDATE_API`)를 처음부터 계획에 넣는다. 교체 스크립트도 세 OS에서 실제로 돌리는 테스트를 먼저 썼으면 ②③을 더 일찍 잡았다.
