# 화면을 계획 열·실행 열 두 줄기로 다시 배치하고, 새 세션에 cxa식 이름·모델을 붙이고, 실제 모델·effort를 보인다

## 목표 / 하지 않을 것
- 목표:
  - 화면을 세션 역할에 맞춰 왼쪽 **계획 열**과 오른쪽 **실행 열**로 나눈다. 계획 열은 기록 영역(후속후보·최근 완료)과 계획 세션을, 실행 열은 진행 영역(「지금」·백로그)과 실행 세션을 담는다. 각 열은 위에 목록, 아래에 그 역할의 터미널을 둔다.
  - 터미널이 지금(패널 260px, 약 15줄)보다 두 배 이상 보이게 한다. 프로젝트 영역을 좁은 레일로 접어 터미널 폭도 넓힐 수 있게 한다.
  - Anvil이 새로 띄우는 세션에 cxa(`~/cc.sh`) 규칙의 이름과 모델을 붙인다. 이름 맨 앞에는 `[Anvil]`을 붙인다.
- 하지 않을 것:
  - tmux 내부 이름(`anvil-<키>-plan|run`) 변경. 상태 파일·훅·떠 있는 세션의 키라 그대로 둔다.
  - 이미 떠 있는 세션의 이름 바꾸기. 새로 띄울 때만 적용한다.
  - 터미널 글꼴 크기 변경(이미 12px), 사이드바 접기 단축키.
  - 960px보다 좁은 창 지원(앱 `min-width: 960px` 유지).
  - 보드 버튼 규칙(무엇을 어느 세션에 채우는지, 막는 조건) 변경. 버튼은 자리만 옮긴다.
  - `.forge/`에 쓰기(ADR 261017-211602 그대로).

## 정본
- 용어: `.forge/CONTEXT.md`의 계획 세션 · 실행 세션 · 진행 영역 · 기록 영역 · 후속후보
- ADR: `.forge/adr/261017-211601-sessions-on-dedicated-tmux-socket.md`(tmux 이름은 내부 키), `.forge/adr/261017-211602-anvil-never-writes-forge.md`
- 시안(합의본): https://claude.ai/artifact/KVA7k6tZtRJd6oK8Cs9bZv — A안 '역할 두 줄기'. 계획 열 위쪽 탭, 한 줄 카드, 「지금」 띠, 터미널 머리줄 이름·모델.
- 세션 이름·모델 규칙(cxa `~/cc.sh` 기준 + `[Anvil]` 접두어)
  - 이름: `[Anvil] [<프로젝트 폴더 이름 그대로>] PLAN` / `… RUN`. 예: `[Anvil] [BibleMap] PLAN`. 폴더 이름은 대소문자를 바꾸지 않는다(cc.sh가 `basename`을 그대로 씀).
  - 붙이는 방법: `claude -n "<이름>" --model <opus|sonnet> --settings <훅>`. 계획 = `opus`, 실행 = `sonnet`(cc.sh와 같은 별칭 — 늘 최신).
  - `CC_SESSION_NAME=<이름>`을 세션 환경에 넣는다(tmux `-e`). 그래야 전역 훅 `~/.claude/hooks/cc-session-name.sh`(SessionStart, matcher `clear`)가 `/clear` 뒤에 이름을 다시 붙인다.
  - `[Anvil]` 접두어가 필요한 이유: cxa(`~/cc-all.sh`)는 이름이 정확히 `[BibleMap] PLAN`인 세션을 찾아 옮기거나 복구한다. 접두어가 없으면 Anvil 세션을 자기 것으로 보고 건드린다.
  - 이름 규칙은 한 곳(백엔드)에서만 만든다. 터미널 머리줄도 그 값을 받아 쓴다.
- 모델·effort 표시 규칙(실제 값)
  - 머리줄에는 세션이 지금 쓰는 모델과 effort를 보인다(예: `[Anvil] [BibleMap] PLAN · Opus 5.5 · high`). `/effort`·`/model`로 바꾸면 따라간다.
  - 값의 출처: claude가 상태줄 명령에 넘기는 JSON의 `model.display_name`과 `effort.level`(claude-hud `src/effort.ts`가 같은 필드를 읽는다 — 옛 형식인 문자열 `effort`도 받는다). 훅 입력에는 이 값이 없다.
  - Anvil은 훅과 같은 `--settings`로 **상태줄 래퍼**를 넣는다. 래퍼는 받은 JSON에서 두 값을 세션별 파일에 기록한 뒤, 같은 입력으로 원래 상태줄 명령을 실행해 출력을 그대로 내보낸다. 사용자가 보는 상태줄은 바뀌지 않는다.
  - 원래 상태줄 명령은 claude와 같은 우선순위로 찾는다: 프로젝트 `.claude/settings.local.json` → `.claude/settings.json` → `~/.claude/settings.json`의 `statusLine.command`. 셋 다 없으면 아무것도 그리지 않는다.
  - 기록 파일은 훅 상태 파일(`sessions/<이름>.json`)과 겹치지 않게 둔다. `states()`가 그 폴더의 `*.json`을 모두 세션으로 읽으므로 확장자나 폴더를 달리한다. 쓰기는 원자적으로(임시 파일 → 이름 바꾸기) 하고, 상태줄을 늦추지 않게 가볍게 한다.
  - 상태줄이 처음 그려지기 전에는 띄울 때 지정한 모델(opus/sonnet)만 보이고, effort는 숨긴다.
- 배치 규칙
  - 머리줄(전체 폭): 프로젝트 이름, 브랜치 칩, root 경고, 오른쪽에 '다음 단계 ▸'. `.forge` 읽기 실패와 명령 채우기 실패는 머리줄 바로 아래 전체 폭 띠로 띄운다.
  - 계획 열 위쪽: `[후속후보 | 최근 완료]` 탭(기본 후속후보). 후속후보 탭에 '숨긴 항목 보기 (N)' 토글을 유지한다. 최근 완료 탭에 '전체 기록 보기'를 유지한다.
  - 실행 열 위쪽: 「지금」 띠 한 줄(번호·제목, 계획→실행·검증→회고→봉인 단계, plan·run 등 문서 버튼). 그 아래 백로그.
    - 진행 중인 작업이 없으면 띠에 "진행 중인 작업 없음"과 회고 대기 작업 링크를 보인다.
    - 목표 루프가 있으면 띠 아래 한 줄에 루프 상태(정지 사유·재계획 횟수·검사 결과)와 loop 문서 버튼을 붙인다.
  - 목록 카드는 한 줄(높이 36px 안팎)이다. 제목은 말줄임, 출처·날짜·우선순위는 같은 줄 오른쪽, 버튼도 같은 줄에 둔다. 터치 타깃·포커스 링 규칙은 기존 `app.css`를 따른다.
  - 아래쪽: 계획 세션 | 실행 세션 터미널. 터미널 머리줄에 상태·연결 작업과 함께 세션 이름·모델·effort를 보인다.
  - 경계: 세로 경계(계획↔실행) 하나가 목록과 터미널을 함께 나눈다. 가로 경계(목록↔터미널) 하나가 두 열을 함께 나눈다. 가로 경계 기본값은 목록 영역이 본문 높이의 약 1/3이다. 두 경계 위치는 앱 전체 설정으로 기억한다(localStorage, 읽기·쓰기는 try/catch).
  - 문서 탭: 문서는 위쪽 목록 영역의 두 열을 합친 전체 폭에 연다. 터미널 두 개는 아래에 그대로 남는다(지금과 같은 동작).
  - 상태줄: 프로젝트·브랜치, 백로그·후속후보 개수, 다른 프로젝트 입력 대기 알림(기존 그대로).
  - 프로젝트 영역 접기: 맨 위 «/» 버튼으로 208px 목록 ↔ 약 48px **좁은 레일**을 오간다. 레일 항목(높이 44px)은 프로젝트 이름 앞 두 글자와 세션 상태 점(입력 대기는 노랑)만 보이고, 현재 프로젝트는 강조한다. 마우스를 올리면 전체 이름이 뜬다(`title`). 접은 채로 프로젝트를 바꿀 수 있다. ＋(추가)는 아이콘 버튼으로 남고, ×(등록 해제)는 펼쳤을 때만 있다. 접힘 상태는 경계 위치처럼 localStorage에 기억한다. 접고 펼치면 터미널이 다시 맞춰진다(fit → `term_resize`).
- 완료 정의(DoD)
  1. `env PATH=/opt/homebrew/opt/rustup/bin:/opt/homebrew/bin:/usr/bin:/bin cargo test --manifest-path src-tauri/Cargo.toml 2>&1 | grep -c 'session_title.* ok'` → 1 이상. 테스트는 이름(`[Anvil] [BibleMap] PLAN`, 대소문자 보존)과 모델(plan→opus, run→sonnet)을 확인한다. 같은 명령의 전체 실행 결과는 exit 0이고 기존 22개 테스트도 통과한다.
  2. 앱에서 BibleMap 계획 세션을 새로 연 뒤 `ps -o command= -p $(tmux -L anvil display -p -t <계획 tmux 이름> '#{pane_pid}')` → `-n [Anvil] [BibleMap] PLAN`과 `--model opus`를 둘 다 포함한다. 실행 세션은 `… RUN`과 `--model sonnet`을 포함한다.
  3. 그 계획 세션에서 `/clear`를 한 뒤 `claude agents --json | jq -r '.[].name' | grep -cx '\[Anvil\] \[BibleMap\] PLAN'` → 1(`/clear` 뒤에도 이름 유지).
  4. Anvil 세션이 떠 있는 상태에서 `~/cc-all.sh --dry-run 2>&1 | grep -c '\[Anvil\]'` → 0(cxa가 Anvil 세션을 건드리지 않음).
  5. `npm run check` → `0 ERRORS`.
  5a. 새로 연 계획 세션이 첫 응답을 마친 뒤, 세션별 모델·effort 기록 파일에 effort `high`(지금 `modelSettings`의 opus 값)가 들어 있다. 그 세션에서 `/effort low`를 실행하고 다음 응답 뒤에 다시 보면 `low`로 바뀌어 있고, 머리줄도 `low`를 보인다(머리줄은 UAT (f)).
  6a. 같은 창 크기에서 프로젝트 영역을 펼쳤을 때와 접었을 때 각각 `tmux -L anvil list-clients -F '#{session_name} #{client_width}'` → 접었을 때 계획·실행 세션 모두 8칸 이상 넓다(약 160px을 두 터미널이 나눔).
  6. 창 높이 900px 이상에서 기본 배치로 `tmux -L anvil list-clients -F '#{session_name} #{client_height}'` → 계획·실행 세션 모두 30 이상(지금 260px 패널 ≈ 15줄의 두 배).
  7. UAT(사람 판정 — 배치와 끌기는 화면 판단):
     - (a) 계획 열 위에 `[후속후보 | 최근 완료]` 탭, 아래 계획 터미널이 있다. 실행 열 위에 「지금」 띠와 백로그, 아래 실행 터미널이 있다. 시안과 같은 짜임이다.
     - (b) 세로 경계를 끌면 목록과 터미널이 함께 움직인다. 가로 경계를 끌면 두 열이 함께 움직인다. 앱을 다시 열어도 두 위치가 유지된다.
     - (c) 카드·문서 버튼을 누르면 문서가 위쪽 전체 폭에 열리고, 터미널은 그대로 보이며 입력할 수 있다.
     - (d) 진행 중인 작업이 없는 프로젝트, 목표 루프가 정지된 프로젝트, forge가 없는 프로젝트에서 띠와 빈 상태가 깨지지 않는다.
     - (e) '착수'·'실행'·'다음 단계'가 예전처럼 맞는 세션에 채워지고, 막는 조건 문구가 보인다.
     - (g) 프로젝트 영역을 접으면 좁은 레일로 바뀌고, 레일에서 프로젝트를 바꿀 수 있으며 입력 대기 점이 보인다. 앱을 다시 열어도 접힘이 유지된다.
     - (f) 터미널 머리줄에 세션 이름·모델·effort가 보이고 `/effort`를 바꾸면 따라간다. Anvil 터미널 안 claude 상태줄은 래퍼 전과 같은 모습이다(forge 진행 줄 포함).
  - 작성 시점 사전 상태(2026-10-18):
    - 1 → 0. 앞으로 통과시킬 검사(테스트가 아직 없음). 기존 테스트 22개는 통과.
    - 2·3·5a·6·6a → 측정 불가(앱은 떠 있으나 tmux anvil 서버 없음, 기록 파일은 아직 없음). 앞으로 통과시킬 검사.
    - 4 → 0. 회귀 방지 검사다. 지금은 `[Anvil]` 이름 세션이 없어서 0이고, 생긴 뒤에도 0이어야 한다.
    - 5 → 0 ERRORS. 회귀 방지 검사다(배치를 바꾼 뒤에도 유지).
