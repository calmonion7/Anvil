# Anvil 3/3 — 보드 버튼이 맞는 세션 입력창에 forge 명령을 채우고, 후속후보를 숨길 수 있게 한다

## 목표 / 하지 않을 것
- 목표: 보드에서 forge를 실행한다. 버튼은 세 가지다. '다음 단계'(프로젝트 머리띠)와 '실행'(백로그 카드)은 실행 세션에, '착수'(후속후보 카드)는 계획 세션에 명령을 **채우기만** 하고, Enter는 사람이 누른다. 후속후보는 숨길 수 있고, 숨긴 표시는 앱 데이터에 남는다.
- 하지 않을 것:
  - 버튼이 Enter까지 치는 일, 명령 대기열
  - 명령 팔레트(Cmd+Shift+P)
  - `.forge/`를 고치는 버튼(백로그 삭제·우선순위 변경 등 — ADR 261017-211602)
  - forge 쪽 후속후보 표준화(사용자가 forge에 따로 요청함)

## 정본
- 용어: `.forge/CONTEXT.md`의 계획 세션 · 실행 세션 · 세션 상태 · 후속후보
- ADR: `.forge/adr/261017-211602-anvil-never-writes-forge.md`, `.forge/adr/261017-211601-sessions-on-dedicated-tmux-socket.md`
- 버튼 규칙
  - 보내는 곳: 착수 → 계획 세션, 실행·다음 단계 → 실행 세션. 그 역할의 세션이 없으면 새로 띄우고, 훅이 SessionStart(입력 대기)를 알린 뒤에 채운다.
  - 채우는 방법: `tmux send-keys -l`로 글자만 보낸다. Enter는 보내지 않는다. 채운 뒤 그 세션 패널로 초점을 옮긴다.
  - 채우는 명령: 다음 단계는 `/forge:fg-next`. 실행은 `/forge:fg-run #<N>`이고, fg-run이 번호 인자를 인식하지 못하면 `/forge:fg-run`만 채운다. 착수는 `/forge:fg-ask <후속후보 문장> (출처: <slug>)`.
  - 막는 조건: 대상 세션이 작업 중이면 버튼을 끄고 `#N 실행 중`(실행 세션) / `계획 세션 작업 중`(계획 세션)을 보여 준다. 입력 대기여도 대화 중간일 수 있으니, 채우기만 하는 규칙이 안전장치다.
  - 후속후보 숨김: 앱 데이터 `hidden-followups.json`에 둔다. 키는 (프로젝트, 출처 파일 경로, 항목 문장)이다. 열 머리에 '숨긴 항목 보기' 토글을 두고 거기서 되돌릴 수 있다.
- 완료 정의(DoD)
  1. BibleMap 보드의 첫 후속후보에서 '착수'를 누른 뒤 `tmux -L anvil capture-pane -p -t anvil-<키>-plan | grep -c '/forge:fg-ask'` → 1 이상. 그 세션 상태 파일의 `state`는 여전히 입력 대기다(Enter가 눌리지 않았다는 증거).
  2. 후속후보 하나를 숨긴 뒤 앱을 다시 열고 `cat "<앱 데이터>/hidden-followups.json"` → 그 항목의 출처 경로와 문장이 들어 있다. 보드에도 다시 나오지 않는다.
  3. fg-run 번호 인자 재현 — 실행 세션에서 `/forge:fg-run #<백로그에 있는 번호>`를 직접 한 번 보내 fg-run이 메뉴 없이 그 작업을 고르는지 확인하고, 결과에 따라 '실행' 버튼이 채우는 문장을 정한다(실행 기록에 결과를 남긴다).
  4. UAT(사람 판정 — 버튼 상태와 초점 이동은 화면 판단):
     - (a) 실행 세션이 작업 중일 때 '실행'·'다음 단계'가 꺼지고 `#N 실행 중`이 보인다.
     - (b) 세션이 없는 프로젝트에서 '착수'를 누르면 계획 세션이 새로 뜬 뒤 명령이 채워진다.
     - (c) 채운 뒤 초점이 그 패널로 가서 Enter만 누르면 진행된다.
  - 작성 시점 사전 상태(2026-10-17): 앱·tmux 서버가 없어 1·2 실행 불가, 3은 재현 전. 모두 앞으로 통과시켜야 하는 검사다.
