# 준비물 확인 중에는 '확인 중…'을 보이고 옛 결과를 숨긴다 (v0.1.7)

## 목표 / 하지 않을 것
- 목표: 준비물 띠가 떠 있는 동안 확인(`deps_status`)이 돌면 띠 문구 자리에 '확인 중…'을 보이고, 설치 전에 받아 둔 '필요: …' 문구는 숨기며, [다시 확인]·[설치] 버튼을 끈다. 늦게 도착한 옛 확인 응답이 더 새 결과를 덮지 못하게 한다. v0.1.7로 배포한다.
  - 계기(후속후보 fu-6f1dafa02d5b, task 15 S5): WSL1 VM에서 [설치] 뒤 띠가 '필요: node 22 이상 / ✓ node 22 이상 설치됨'으로 남았다가, [다시 확인]을 누르자 사라졌다.
  - 원인 가설(코드를 읽고 세움, VM 재현 없음): `installDeps()`가 끝나고 부르는 `checkDeps()`가 결과를 돌려줄 때까지 띠는 설치 전의 `deps`를 그대로 보인다. WSL1 ARM VM에서는 확인 한 번에 `wsl.exe` 호출이 5번쯤 들어 수십 초가 걸린다. 그 사이에는 확인 중이라는 표시가 없다. 백엔드에는 캐시가 없다(`deps::status()`는 매번 새로 확인).
- 하지 않을 것:
  - 백엔드(`src-tauri/`) 변경 — 확인이 일시적으로 실패하는 경우(`wsl.exe` 실패를 '없음'으로 보는 것)는 증거가 없어 다루지 않는다. VM에서 증상이 다시 나오면 새 후속후보로 남긴다.
  - VM 사람 확인 — e2e만으로 확인한다(결정 4).
  - 앱 시작 때의 첫 확인 — 그때는 결과가 오기 전까지 띠가 없으므로 그대로 둔다.
  - [설치] 직후 항목별 결과(`depsSteps`)를 지우는 것 — task 9의 결정대로 [설치]가 끝나면 결과는 계속 보여야 한다.
