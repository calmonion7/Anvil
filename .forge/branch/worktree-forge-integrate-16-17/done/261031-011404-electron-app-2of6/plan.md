# 재부팅·서버 재시작 뒤 세션을 대화째 복구 (데스크톱 앱 2/6)

## 목표 / 하지 않을 것
- 목표: 재부팅이나 서버 종료로 세션(claude 프로세스)이 끝나도, 다음에 앱을 열면 열려 있던 세션이 같은 프로젝트·역할로 `claude --resume <대화 ID>`로 다시 떠서 이전 대화가 화면에 그대로 보인다. 서버가 어떻게 내려갔는지(재부팅, 활동 모니터 「종료」·「강제 종료」, `kill`, 업데이트 재시작)와 상관없이 복구한다.
- 하지 않을 것:
  - 끊긴 동작을 자동으로 이어 치기(「계속」 자동 입력 — 사람이 확인한다)
  - 「복구됨」 화면 표시: claude가 이어 열면 이전 대화를 스스로 그린다(실측 2026-10-30). 작업 도중 끊긴 것이 화면에서 티 나지 않으면 UAT 뒤 별도 작업으로 넣는다.
  - claude가 서버가 살아 있는 동안 저절로 죽은 경우(크래시)를 `/exit`와 가르기
  - 로그인 자동 시작
  - 업데이트 경로(5/6이 이 기능을 재사용한다)
  - Windows·Linux 확인(4/6)

## 근거
- 용어: 세션·계획 세션·실행 세션·세션 상태 — `.forge/CONTEXT.md`
- 관련 ADR: `adr/261030-005852-electron-desktop-shell.md`(재부팅·서버 재시작 뒤 세션을 대화째 복구, 복구는 앱을 열 때 — 서버가 뜰 때 하므로 같다)
- 실측 근거:
  - 서버가 꺼지면 그 서버가 쥔 claude도 끝난다. 1/6 UAT에서 사용자가 서버를 끄자 세션이 `ended`가 됐고, 4초 뒤 새 서버가 떴다(2026-10-30).
  - 대화 ID는 훅이 `<데이터 폴더>/sessions/<세션 이름>.json`의 `session_id`에 남긴다(`server/hooks/anvil-hook.js`). 그런데 세션을 새로 띄울 때 이 파일을 지운다(`server/session.js` `start`의 `rmSync`). 그래서 복구 목록은 이 파일과 따로 둬야 한다.
  - `claude --resume <id>`는 이전 대화와 세션 이름을 화면에 다시 그린다. 2026-10-30 pty로 `--fork-session`과 함께 띄워 확인했고, 입력을 보내지 않으면 새 기록 파일은 생기지 않았다.
- 회고 `retro/261030-212232-electron-app-1of6.md`:
  - "서버가 꺼져도 세션 복구"는 사용자가 1/6 UAT에서 먼저 기대한 동작이다. 서버를 직접 끄는 경우를 시나리오에 넣는다.
  - DoD 기준선은 여러 번 재서 간헐 실패를 먼저 가린다.
  - OS가 보내는 이벤트·신호는 테스트에서 직접 보낸다.
- 정해진 것(그릴링 2026-10-30):
  1. 복구 안 함(목록에서 뺌): 사람이 끝낸 경우다. [세션 종료]를 누르거나, 서버가 살아 있는 동안 claude가 스스로 끝난 경우가 여기 해당한다. 이 밖의 끝남은 모두 복구한다(목록에 남김). 일반 종료 신호(SIGTERM)와 강제 종료 신호(SIGKILL) 둘 다 테스트로 고정한다. 서버에 종료 신호를 받아 세션을 정리하는 처리가 생기면 목록이 비는 회귀를 막기 위해서다.
  2. 대화 ID가 없는 항목(훅이 불리기 전에 서버가 내려간 경우 — 폴더 신뢰 확인 중 재부팅 등)은 `--resume` 없이 새 claude로 띄운다.
  3. 복구 목록은 `<데이터 폴더>/restore.json`이다. 다시 띄울 때는 지금 설정된 역할별 모델을 쓴다. 등록이 해제된 프로젝트의 항목은 띄우지 않고 목록에서 뺀다.
- 완료 정의(DoD):
  1. `node --test server/` → 0 실패. 새 테스트 포함:
     - 세션을 시작하면 복구 목록에 프로젝트·역할·세션 이름이 남고, 훅이 대화 ID를 알리면 목록에도 반영된다.
     - [세션 종료](`session_kill`)로 끈 세션과, 서버가 살아 있는 동안 claude가 스스로 끝난 세션은 목록에서 빠진다.
     - 세션이 살아 있는 서버를 SIGTERM으로, 또 SIGKILL로 내린 뒤에도 목록이 그대로 남는다(실제 진입점 `server/main.js`를 띄워 확인).
     - 서버를 다시 띄우면 목록의 세션이 `--resume <ID>`와 같은 세션 이름·작업 폴더로 뜬다(가짜 claude가 받은 인자로 확인). 대화 ID가 없는 항목은 `--resume` 없이 뜬다.
     - 등록이 해제된 프로젝트의 항목은 띄우지 않고 목록에서 빠진다.
     - 사전 상태(실측 2026-10-30): 82/82 통과(두 번 재서 간헐 실패 없음). 복구 목록·복구 코드 없음(`grep -c resume server/session.js` → 0). 전진 검사.
  2. `npx playwright test` → 0 실패.
     - 사전 상태(실측): 43 passed. 회귀 방지 검사라 미리 통과가 정상이다.
  3. Electron 스모크(`npm run test:app`)에 한 단계를 더한다: 세션 열기 → 서버를 SIGKILL로 종료 → 앱 다시 실행 → 같은 세션 이름이 다시 살아 있고(`session_states`), 가짜 claude가 `--resume <ID>`를 받았다. 프로젝트는 임시 데이터 폴더의 `projects.json`에 미리 적어 둔다.
     - 사전 상태(실측): 1 passed. 1/6 단계는 회귀 방지 검사이고, 새 단계는 전진 검사다.
  4. UAT(이 Mac, 사람): 계획 세션에서 claude와 대화 → 백그라운드 서버를 끈다(`pkill -9 -f server/main.js`, 또는 활동 모니터에서 「강제 종료」) → 앱을 다시 열면 같은 대화가 보이고 이어서 말할 수 있다 → 보드에서 [세션 종료]로 끈 뒤 서버를 다시 꺼도 그 세션은 돌아오지 않는다. 가능하면 실제 재부팅으로 한 번 더 본다.

## 작업 조각
- [ ] S1. **복구 목록 기록**: 세션 시작, 훅의 대화 ID 갱신(`sessions/` 감시), 사용자 종료 때 `restore.json`을 원자적으로(임시 파일 → rename) 갱신한다. 서버가 살아 있는 동안 claude가 스스로 끝난 세션(pty `onExit`)은 뺀다. 서버가 내려가면서 끝난 세션은 남긴다. 서버는 종료 신호를 받아도 세션을 정리하지 않는다. 완료 기준: DoD 1의 첫 세 항목.
- [ ] S2. **서버 시작 때 복구** (depends: S1): 서버가 뜰 때 목록의 항목마다 같은 세션 이름·작업 폴더·지금 모델 설정으로 claude를 띄운다. 대화 ID가 있으면 `--resume <ID>`를 붙이고, 없으면 붙이지 않는다. 등록이 해제된 프로젝트의 항목은 뺀다. 복구한 claude가 바로 끝나면 S1 규칙대로 목록에서 빠지고 세션 상태 「종료」로 보인다. 완료 기준: DoD 1 나머지, DoD 3.
