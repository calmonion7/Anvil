# 2026-10-30 — 데스크톱 앱 1/6: Electron 창 + 앱과 떨어진 서버(단일 실행·유휴 종료·node 대체 실행 파일)·mac dmg

## 계획 대비 실제
- 계획대로 된 것:
  - S2·S3·S4는 계획한 구조 그대로 들어갔다. 세션 테스트 전체를 Electron 런타임에서 다시 돌리는 테스트(`server/test/electron.test.js`)가 "훅이 `node` 대체 실행 파일로 돈다"까지 한 번에 판정해 줬다. 가짜 claude가 실제로 훅을 부르기 때문이다.
  - 사람 UAT의 기능 항목은 고친 뒤 모두 통과했다. 같은 서버·같은 claude 프로세스로 대화가 이어졌다.
- 어긋난 것:
  - **S1의 전제가 틀렸다.** node-pty 1.1.0은 N-API prebuild라 Electron 45에서 다시 빌드하지 않고 그대로 돈다(실측). `@electron/rebuild`와 ABI별 산출물 분리는 필요 없었다.
  - **패키징된 앱에서만 생기는 결함이 개발 실행에서는 안 보였다.** `server/pty.js`가 asar 안 경로에 chmod하다 `ENOTDIR`로 서버가 기동하자마자 죽었다. 설치된 바이너리로 asar 속 서버·훅·pty를 직접 돌리는 점검 스크립트로 잡았다.
  - **UAT에서 다시 열 때 `ERR_ABORTED` 오류창이 떴다.** Finder·Dock으로 열면 macOS가 시작 직후 `activate`를 보내 `open()`이 두 번 돌았다. Playwright `_electron`은 이 이벤트를 보내지 않아 스모크가 통과했었다. 스모크에 `app.emit('activate')`를 넣어 재현한 뒤 고쳤다.
  - 보안 리뷰에서 major 2건이 나왔다. 하나는 낡은 `server.json`의 포트에 다른 사용자의 가짜 서버가 있으면 거기에 붙는 것, 다른 하나는 권한 요청 자동 허용·iframe 미차단이다. 회고가 넣으라고 한 보안 렌즈 리뷰가 이번에도 값을 했다.
  - 기준선에서 이미 깨져 있던 것이 둘 나왔다. `cargo test` 한 건이 간헐 실패했고(5번 중 2번), 세션 재생 테스트는 경쟁 상태로 10번 중 4번 실패했다. 기준선을 한 번만 쟀으면 이번 변경 탓으로 오해했을 것이다.
  - 직전 작업 UAT 때 띄운 옛 서버가 4517을 잡고 있어 UAT 전에 꺼야 했다. 사용자는 서버를 직접 끈 뒤 세션이 복구되지 않는 것을 보고 2/6 범위의 기대를 먼저 드러냈다.

## 배운 점
- 다음엔 다르게:
  - **설치 파일을 만드는 조각은 설치된 바이너리로 서버를 직접 돌려 보는 점검까지가 완료 기준이다.** asar·`app.asar.unpacked`·`process.execPath`가 개발 실행과 다르다. 5/6(릴리스)·4/6(Windows·Linux)에서도 패키징 산출물로 서버 기동·훅·pty를 확인한다.
  - **OS가 앱을 열 때 보내는 이벤트(`activate`, `open-url`, `second-instance`)는 Playwright `_electron`이 흉내 내지 않는다.** 스모크에서 `app.emit(...)`으로 직접 보내 본다. 비동기 `open()`처럼 여러 경로에서 부르는 함수는 처음부터 진행 중인 작업을 같이 기다리게 짠다.
  - **DoD 기준선은 테스트를 여러 번 돌려 간헐 실패를 먼저 가린다.** 한 번만 재면 이미 있던 간헐 실패를 이번 변경 탓으로 오해한다. 이번에 `cargo test`·세션 재생 두 건이 그랬다.
  - **UAT 전에 옛 서버가 떠 있는지 확인한다**(`lsof -nP -iTCP:4517 -sTCP:LISTEN`). 이전 세션이 띄운 백그라운드 서버가 포트를 쥐고 있을 수 있다.
  - **"앱을 꺼도 세션 유지"와 "서버가 꺼져도 세션 복구"는 사용자에게 같은 기대로 들린다.** 2/6 그릴링에서 서버를 직접 끄는 경우(활동 모니터 등)를 시나리오로 넣는다.
  - 유지: 연결 상태·토큰 감시처럼 "고치면 통과하는" 테스트는 고친 부분을 빼고 돌려(변이 검사) 테스트가 실제로 결함을 잡는지 확인한다.
