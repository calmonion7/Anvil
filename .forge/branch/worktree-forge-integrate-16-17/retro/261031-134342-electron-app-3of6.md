# 2026-10-31 — 데스크톱 앱 3/6: 첫 실행 때 준비물(개발자 도구·claude·forge) 자동 설치와 「준비 중」 화면

## 계획 대비 실제
- 계획대로 된 것:
  - 서버 자동 설치(순서·실패 보고·forge 건너뜀·한 번에 하나만)와 「준비 중」 화면을 테스트 먼저 쓰는 방식으로 넣었다.
  - 깨끗한 UTM macOS VM에서 dmg 설치 → 자동 설치 → 보드 → claude 로그인까지 한 번에 통과했다. 사람이 한 일은 개발자 도구 설치 창 클릭과 화면 판단뿐이었다. SSH 자동화(메모리 「VM test automation」) 덕에 VM 안 손 작업이 거의 없었다.
- 어긋난 것:
  - **Tauri에서 옮기며 "사람이 보는 동작"이 빠졌다.** `deps.rs:211`은 개발자 도구 설치 창을 앞으로 가져왔는데, 명령만 옮기면서 이 처리가 사라졌다. VM에서 설치 창이 Anvil 창 뒤에 숨었고, 화면에는 「설치 중…」만 보여 사람이 [설치]를 눌러야 하는 줄 알 수 없었다. UAT 중에 테스트를 먼저 쓰고 고쳤지만, VM에는 고치기 전 빌드가 들어 있어 이 수정은 화면으로 확인하지 못했다.
  - 기존 준비물 띠를 「준비 중」 화면으로 바꾸면서 띠 전제 e2e 4개를 손봤다(2개는 옮기고 2개는 지움).
  - 360px 측정에서 앱 전체가 원래 가로로 넘친다는 것을 알았다(보드만 있을 때도 문서 폭 987px). 이 화면 테스트는 화면 자체만 보게 좁혔다.

## 배운 점
- 다음엔 다르게:
  - **다른 구현에서 기능을 옮길 때는 명령 목록뿐 아니라 "사람이 보는 부수 동작"(창 앞으로 가져오기, 안내 문구, 기다림 표시)을 따로 목록으로 뽑아 옮긴다.** 원본 코드의 `osascript`·`activate`·사용자 안내 문자열을 grep하면 찾을 수 있다.
  - **사람이 끼는 단계(설치 창 클릭 등)가 있는 항목은 화면에 "지금 사람이 할 일"을 따로 보인다.** 진행 상태 하나(「설치 중…」)로는 기다리는 것인지 눌러야 하는 것인지 구분되지 않는다.
  - **UAT에서 고친 부분은 다시 빌드한 산출물로 한 번 더 보거나, 못 봤다고 기록한다.** VM UAT처럼 다시 하는 비용이 큰 확인은, 고치기 전 빌드로 흐름을 보고 수정은 테스트로 확인했다고 나눠서 적는다(이번에 그렇게 했다 — 유지).
  - 좁은 폭 측정은 먼저 기준 화면(바꾸지 않은 보드)을 같은 폭으로 재서, 새 화면 탓인지 원래 배치 탓인지 가른다.
