# 입력 대기 알림은 앱 주 프로세스가 띄우고, Windows·Linux는 창을 닫으면 트레이에 남는다

ADR 261030-005852로 서버는 앱과 떨어져 돈다. 앱을 꺼도 세션은 계속 일하고, 「입력 대기」로 바뀌는 것은 claude 훅이 `<데이터 폴더>/sessions/`에 남긴다. 옛 Tauri 앱은 "앱이 켜져 있으면 앱이, 꺼져 있으면 훅이" OS 알림을 띄웠다. Electron으로 옮긴 뒤 알림을 다시 만들면서 누가 언제 알릴지를 새로 정했다(작업 #26).

## 결정

- **알림은 앱이 켜져 있을 때만, 앱 주 프로세스가 띄운다.** 주 프로세스가 `sessions/`를 직접 지켜보다 상태가 다른 값에서 `waiting`으로 바뀌는 순간 한 번 띄운다. 포커스된 Anvil 창이 있으면 띄우지 않는다. 서버나 훅은 알리지 않는다. 화면(렌더러)에서 IPC로 받지 않는 것은 창을 닫아도 알림이 끊기지 않게 하려는 것이다.
- **Windows·Linux는 창을 다 닫으면 트레이에 남는다**(macOS의 Dock과 같은 효과). 창은 숨기지 않고 닫는다. 그래야 서버의 "세션도 창도 없이 5분이면 내려감" 규칙이 그대로다. 트레이 메뉴는 [열기]·[끝내기]이고, 처음 트레이로 들어갈 때 한 번 안내한다. 트레이가 안 보이는 데스크톱(확장 없는 GNOME 등)에서도 다시 실행하거나 알림을 누르면 창이 열린다.
- **macOS는 `osascript display notification`으로 띄운다.** 서명 없는(ad-hoc) Electron 앱의 알림은 macOS가 권한 창 없이 거절한다(실측 2026-11-01, Electron 45.1.0, 새 번들 ID로도 `Notifications are not allowed for this application`). 그래서 macOS 알림은 아이콘이 '스크립트 편집기'로 나오고, 눌러도 Anvil로 오지 않는다. Windows·Linux는 Electron 알림이라 누르면 그 프로젝트가 골라진 창이 열린다.

## 고려한 다른 길

- **서버(또는 훅)가 늘 알린다** — 앱이 완전히 꺼져도 알림이 오고 코드 경로가 하나다. 사람이 처음에는 "꺼져 있을 때도"를 골랐다가, 알림을 눌러 Anvil로 오는 쪽을 택하며 바꿨다. 옛 Tauri처럼 "앱이 켜져 있나" 판정(`app.pid`·`tasklist.exe`)을 다시 들일 필요도 없어졌다.
- **트레이 없이 Windows·Linux는 창을 닫으면 끈다(전 동작)** — 그러면 창을 닫아 두고 기다리는 가장 흔한 순간에 알림이 오지 않는다.

## 결과

- 앱을 Cmd+Q·트레이 [끝내기]로 끄면 세션은 살아 있어도 알림은 없다.
- macOS에서 알림을 눌러 그 프로젝트로 가려면 서명·공증이 필요할 것으로 본다(짐작 — 후속후보 fu-06dd2fdd4a5c).
- 알림 언어는 OS 언어를 따른다(주 프로세스는 화면의 언어 설정을 모른다 — fu-d1be78e58052).
