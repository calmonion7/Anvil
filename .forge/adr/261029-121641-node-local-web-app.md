# Anvil을 Node 로컬 웹앱으로 바꾸고, 세션은 tmux 대신 서버가 쥔다

Tauri(Rust) 데스크톱 앱은 가볍지만, 세 OS를 지원하면서 사용자 설치와 개발자 빌드·테스트가 모두 무거워졌다. 사용자는 서명되지 않은 앱 경고를 넘겨야 했고, Windows는 관리자 권한과 재부팅이 필요한 WSL을 먼저 갖춰야 했다. 개발자는 릴리스마다 4플랫폼 빌드와 업데이터 서명을 거쳐야 했고, e2e는 tauri-driver(Linux)와 웹뷰 디버그 포트(Windows)로 나뉘었으며 mac에서는 돌지 않았다. tmux·jq 정적 바이너리도 OS별로 미리 빌드해야 했다. 그 부담의 대부분은 Rust 자체가 아니라 "OS마다 다른 네이티브 앱"이라는 형태에서 나왔다. 그래서 형태를 바꾼다.

## 결정

- **앱 = Node 서버 + 브라우저 화면.** 화면(SvelteKit·xterm.js)은 그대로 쓰고, 백엔드만 Node로 옮긴다. 서버는 `127.0.0.1`의 고정 포트에만 열고, 토큰과 Origin 검사로 다른 웹페이지가 접근하지 못하게 막는다. 터미널을 여는 서버이기 때문이다. 창은 브라우저 탭이고, 원하면 PWA로 설치한다.
- **세션은 서버가 node-pty로 직접 쥔다. tmux는 쓰지 않는다.** tmux를 쓴 이유(ADR 261017-211601)는 "앱을 닫으면 세션이 죽는다"였다. 서버가 로그인할 때 자동으로 시작되는 상주 프로세스가 되면서 브라우저를 닫아도 세션이 남으니, 그 이유가 사라졌다. 그 결과 세 OS의 코드 경로가 하나로 합쳐지고, **Windows는 WSL 없이 네이티브로** 돈다. 대가로 서버가 재시작되면 세션이 끝난다. 그래서 업데이트는 작업 중인 세션이 없을 때만 재시작한다.
- **진입은 한 줄 설치 스크립트**(`install.sh` · `install.ps1`)다. 설치 스크립트가 준비물(node·claude·forge·git)을 설치하고, 로그인 자동 시작을 등록한 뒤 브라우저를 연다. 앱 안의 [설치] 기능은 없앤다. 앱은 빠진 준비물을 보여 주고, 설치 줄을 다시 실행하라고 안내만 한다.
- **배포는 GitHub Releases tarball**(`npm pack` 한 번)이다. 설치·업데이트 모두 `npm i -g <tgz URL>`로 하고, npm 계정은 필요 없다. 이 Mac도 사용자와 같은 릴리스를 따라간다(launchd main 추종은 폐기).

## 고려한 대안

- **Electron**: OS별 WebView 차이는 없애지만 설치 파일, 서명, OS별 빌드, WSL 연결이 그대로 남고 용량이 100MB를 넘는다. 개발자 부담이 거의 줄지 않는다.
- **tmux 유지 + Windows는 WSL**: 세션이 서버 재시작까지 버티지만, Windows의 WSL 준비(관리자 권한·재부팅)라는 가장 큰 진입 장벽이 남는다.
- **혼합(mac·Linux는 tmux, Windows는 node-pty)**: 코드 경로가 둘이 되어 줄이려던 테스트 부담이 되살아난다.

## 결과

- 이 ADR은 다음 ADR들을 대체한다: 261017-211600(Tauri), 261017-211601(tmux 세션), 261018-190555(launchd 로컬 빌드 추종), 261024-202909·261025-163349(tmux·jq 내장). 대체된 ADR은 전환의 마지막 단계(4/4)에서 은퇴시킨다.
- 기존 Tauri 사용자의 데이터는 옮기지 않는다(새로 시작). 입력 대기 알림은 전환 범위에서 빼고 별도 작업으로 다룬다.
- 처음 ADR이 웹앱을 거절한 이유("독립 프로그램이 아니다")는 로그인 자동 시작과 PWA 설치로 갈음한다.
